# Discovery and delivery status

## Evidence

Sensitive infrastructure findings are deliberately excluded from this public repository. A separate Cloudflare Access application, DNS record and tunnel route have been created, and the service is deployed in a dedicated namespace. Existing tunnel ingress entries were preserved; a private rollback snapshot was saved outside the repository. The existing endpoint returned the same unauthenticated status before and after the route change.

The ChatGPT connector subsequently exercised all five original tools through the hosted route. The diagnostics expansion was installed in the existing release after independent review, passing CI, isolated Kubernetes tests, reproducible builds and image scanning. Real-cluster calls from the deployed service account and a temporary loopback-only MCP HTTP listener in the deployed image also exercised the expanded diagnostics. These were separate from connector tests.

On 2026-11-14, a new Codex session exposed all 16 tools through the refreshed connected Kubernetes MCP app. Actual app calls to each tool succeeded, including namespace and cross-namespace discovery, workloads, services, node and pod metrics, node status, and pod diagnosis. Current logs were returned and previous logs were cleanly unavailable for the sampled container. Cross-namespace and namespace pod listings followed continuation tokens to completion. These results are scoped to the sampled resources and current connector session; they are not evidence that ChatGPT rendered the server icon or title. Live token revocation and production rollback remain unverified.

The local Knowledge Vault repository describes Cloudflare Access Managed OAuth and independent origin verification of Access assertions. That is a reference design, not evidence that the current live configuration matches it. Further inspection must avoid saving private topology or credentials to this public repository.

The [containers Kubernetes MCP server](https://github.com/containers/kubernetes-mcp-server) offers Streamable HTTP, pod logs and read-only mode. Its [configuration documentation](https://github.com/containers/kubernetes-mcp-server/blob/main/docs/configuration.md) describes read-only controls as best-effort guardrails. It also offers broader capabilities than this project's narrow diagnostics scope. A small custom prototype is being evaluated to limit API surface; this is not yet a complete adopt/build decision: licensing, maintenance, log bounds, and authentication need a documented comparison before production selection. The [MCP transport specification](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports) defines interoperability requirements; the prototype has not been certified against them.

## Remaining gates

- Hosted authenticated connector calls succeeded. The existing tunnel is Cloudflare-managed, the new route specifies verified origin TLS, and its existing ingress entries were preserved. Independently verifying the connector's certificate-validation behavior and complete route isolation remains outstanding.
- Complete protocol negotiation and conformance using a maintained MCP SDK or demonstrate equivalent behavior. Local smoke tests with the official Python and TypeScript MCP clients initialized, listed five tools and called `list_pods` against a simulated backend; these are not full conformance tests.
- Hosted OAuth discovery and authenticated calls through the ChatGPT connector have passed; the refreshed 16-tool catalog and calls were verified in a new Codex connected-app session. Test real Access revocation semantics. Offline JWT verification alone does not provide immediate revocation. The bearer token mode is not a hosted solution.
- Pod-list continuation was exercised through the connected app and in isolated CI. Validate real Kubernetes API timeouts and deletion races against an isolated cluster. A delayed local TLS endpoint verifies the Kubernetes client's HTTP timeout; other simulated cases cover API errors, oversized and malformed responses, redirects, and projected-token rotation. The guarded kind job covers bounded and oversized logs, untrusted text, multi-container status, concurrency, a restarted container and release removal. See [the test plan](testing/isolated-e2e.md).
- CI runs `mypy --check-untyped-defs` over the server; this is not strict type coverage. Runtime wheels are hash-locked. Two clean x86_64 BuildKit OCI builds with a fixed source epoch and rewritten timestamps produced matching manifest digests in CI at `0c0c315`; two legacy Docker builds without those controls did not. This verifies the controlled build procedure, not every builder or architecture. Pinned Python dependencies passed `pip-audit --disable-pip --no-deps`. The initial Debian image CI scan found 49 high Debian package findings and 5 high findings in pip's bundled packages. Switching to a pinned Alpine image and removing pip after dependency installation removed these findings: CI Trivy's high/critical gate passed on commit `6b4fd63`. The local scanner could not unpack its database due to temporary-storage quota; this result is from CI, not a local scan. Passing a scan does not eliminate unknown or lower-severity vulnerabilities.
- Complete independent review of the exact commit; fix and retest findings. No production deployment or merge before approval.

## Rollback concept

To remove this deployment, remove only its route and Access application, then uninstall its release and verify removal of its associated RBAC, including cluster-scoped bindings when enabled. Do not alter the Knowledge Vault route. This is a proposed plan, not a demonstrated production rollback.
